# BatchFlow v2.0.0-rc.2

Release candidate 2 stabilizes the runtime API and prepares the project for a formal v2.0.0 release.

## API status

The public module path remains:

```text
github.com/rushairer/batchflow/v2
```

Versioning is expressed by the module path and tag, not by public API name prefixes.

Preferred stable entrypoint:

```go
cfg := batchflow.DefaultConfig(executor)
flow, err := batchflow.New(ctx, cfg)
```

Preferred public types:

```go
batchflow.Config
batchflow.Flow
batchflow.RuntimeConfig
batchflow.BackpressureConfig
batchflow.MemoryLimitConfig
batchflow.AdaptiveTuningConfig
```

## Highlights

- Added stable runtime API:
  - `Config`
  - `Flow`
  - `DefaultConfig`
  - `New`
- Added `RuntimeEngine` for sharding, routing, backpressure and memory protection.
- Added shard routing policies:
  - hash
  - round-robin
  - least-loaded
- Added runtime backpressure:
  - block
  - reject
  - timeout
- Added estimated queue memory limiter:
  - `MemoryLimitConfig`
  - `ErrMemoryLimitExceeded`
- Added adaptive tuning policy engine:
  - `AdaptiveTuner`
  - `TuningSignal`
  - `TuningRecommendation`
- Added COPY FROM execution backend:
  - `CopyFromExecutor`
  - `CopyFromClient`
- Added pooled COPY row builder to reduce hot-path allocations.
- Added optional pgx COPY adapter in `adapters/pgxcopy`.
- Added production tuning guide.
- Added benchmark harness skeleton.

## Validation checklist before tagging

Run at repository root:

```bash
go test ./...
go test ./... -race
go test ./benchmark -bench=. -benchmem
```

Run adapter validation:

```bash
cd adapters/pgxcopy
go test ./...
```

## Known RC status

This is still an RC. The API names are now stable, but benchmark numbers and database-specific COPY performance should be verified in the target production environment before final v2.0.0 tagging.
